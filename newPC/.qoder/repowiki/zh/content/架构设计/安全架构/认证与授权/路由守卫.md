## 简介
本文件面向校园管理系统，系统性梳理并文档化 Vue Router 导航守卫的实现与运行机制，重点覆盖：
- 全局前置守卫 beforeEach 的完整逻辑与分支
- 权限验证流程与 401 无权限跳转
- 白名单机制与特殊场景（如单点登录、旧框架桥接）
- 动态路由与权限路由的注册策略
- 路由缓存与预加载（keep-alive、懒加载、缓存开关）
- 异常与边界条件的处理方式

## 架构总览
全局前置守卫在每次路由变更前执行，主要职责：
- 快速放行白名单与特殊入口
- 从查询参数或旧框架 hash 中提取 token 并拉取用户信息
- 校验 to.meta.permissionPath 是否在用户权限集合中
- 未登录统一重定向至登录页

```mermaid
sequenceDiagram
participant U as "用户"
participant R as "Vue Router"
participant G as "全局守卫<br/>beforeEach"
participant S as "Vuex Store"
participant API as "权限/用户接口"
U->>R : 访问目标路由(to)
R->>G : 触发 beforeEach(to, from, next)
G->>G : 检查白名单/特殊入口
alt 在白名单或特殊入口
G-->>R : next()
else 需要鉴权
alt to.query.token 存在
G->>S : 写入 Admin-Token Cookie
G->>S : dispatch(GetInfo)
S->>API : 拉取用户信息/权限
API-->>S : 返回用户/权限数据
else 旧框架 userToken
G->>S : 写入 User-Token Cookie
G->>S : dispatch(FromOldFramework)
S->>API : 桥接旧框架用户
API-->>S : 返回新用户/权限数据
end
G->>G : 校验 to.meta.permissionPath ∈ permission
alt 无权限
G-->>R : next('/401')
else 有权限
G-->>R : next()
end
end
```

## 详细组件分析

### 全局前置守卫 beforeEach 实现
- 白名单与特殊入口
  - 包含登录页、扫码登录、独立运行模式、部分公开页面等
  - 单点登录入口：/system/sysManage 且携带 userToken
- Token 注入与用户信息拉取
  - 优先从 to.query.token 注入 Admin-Token
  - 旧框架桥接：从 location.hash 提取 userToken，写入 User-Token，并调用 FromOldFramework
  - 拉取用户信息后，再进行权限校验
- 权限校验
  - 若路由 meta 中存在 permissionPath，则与用户权限集合比对
  - 无权限跳转至 401 页面
- 登录状态与重定向
  - 未登录根据 pc_login_type 重定向至不同入口
  - 已登录访问 /login 自动重定向至首页

```mermaid
flowchart TD
Start(["进入 beforeEach"]) --> CheckWL["是否命中白名单/特殊入口"]
CheckWL --> |是| Allow1["放行 next()"]
CheckWL --> |否| HasToken{"to.query.token 存在?"}
HasToken --> |是| InjectToken["写入 Admin-Token Cookie"] --> FetchInfo["dispatch(GetInfo)"]
HasToken --> |否| OldUserToken{"location.hash 含 userToken?"}
OldUserToken --> |是| Bridge["写入 User-Token 并 FromOldFramework"] --> CheckPerm
OldUserToken --> |否| HasLocalToken{"store.getters.token 存在?"}
HasLocalToken --> |是| NeedFetch{"roles.length==0?"}
NeedFetch --> |是| FetchInfo2["dispatch(GetInfo)"] --> CheckPerm
NeedFetch --> |否| CheckPerm["校验 to.meta.permissionPath"]
HasLocalToken --> |否| Redirect["根据 pc_login_type 重定向到登录页"] --> End
FetchInfo --> CheckPerm
FetchInfo2 --> CheckPerm
CheckPerm --> |无权限| To401["next('/401')"] --> End
CheckPerm --> |有权限| Allow2["next()"] --> End
Allow1 --> End(["结束"])
Redirect --> End
To401 --> End
Allow2 --> End
```

## 性能考虑
- 懒加载与缓存
  - 路由组件懒加载减少首屏体积
  - 合理使用 isCached/keepCached，避免不必要的内存占用
- 请求去重
  - 旧框架桥接仅首次执行，避免重复请求
- 进度条与异常处理
  - NProgress 精准开始/结束，减少 UI 卡顿感知

## 故障排查指南
- 无法进入受控页面
  - 检查 to.meta.permissionPath 是否正确配置
  - 确认用户权限集合是否包含该路径
- 旧框架桥接失败
  - 确认 location.hash 中 userToken 是否存在
  - 检查 FromOldFramework 接口返回与 Vuex 状态更新
- 登录后仍被重定向
  - 检查 pc_login_type 与重定向逻辑
  - 确认 Cookie 中 token 是否正确写入
- 401 页面频繁出现
  - 核对权限接口返回与 moduleList.js 映射一致性
